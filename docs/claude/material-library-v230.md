## Ловушка прогона: `_httpcache`

`_imp_probe` дважды отдал `NO PROBE OUTPUT` — это НЕ гонка с Chrome и не
регрессия. Причина: зонды делят `--disk-cache-dir=_httpcache`, и если от
прошлого прогона остался зависший Chrome или битый кеш, Chrome выходит с
пустым DOM и пустым stderr. Лечится так:

```
taskkill /F /IM chrome.exe /T
Remove-Item -Recurse -Force _httpcache
py -u _imp_probe.py          # пишет в _imp_out.txt, НЕ в stdout
```

После этого зонд прошёл полностью и побайтово совпал с v229. Зонды пишут
результат в `_<имя>_out.txt` в корне — перенаправлять их stdout в файл
бессмысленно, он пустой.

Ещё: между прогонами остаются питоновские серверы-зомби (порты 88xx).
`Get-Process python,py | Stop-Process -Force` перед серией.

## Что такое v2.30

### Причина 1 — пресет чеканил копию самого себя

Доказано на настоящем `Kubik_NeoTank.json` пользователя: в нём
`standard color="#858585"`, `plastic color="#999999"`, тогда как
`MATERIAL_DEFAULTS` задаёт всем трём `color: null` («следовать теме»).
Замороженный серый не совпадал по `materialDefSig`, id был занят — и в
сборщике `restoreDoc` оставалась одна ветка: **чеканить**. Отсюда
`Solid (imported)` и `Plastic (imported)` в середине полки.

**Измерено: 3 записи на входе → 9 на выходе. Стало 3 → 7** (ровно четыре
настоящих материала файла).

Правка: id, который есть в `MATERIAL_DEFAULTS` (own-property, через
`presetDefaults`), разрешается сам в себя, **если отличие только в ЦВЕТЕ** —
цвет у пресета это данные темы, а не документа. Любое другое отличие (маски,
фаска, roughness, metalness, имя) по-прежнему приезжает своей копией
«Metal (imported)» — правило a2.6x цело.

### Причина 2 (верховая) — редактор примораживал цвет пресета

`meApplyLive` писал `d.color = meColor.value` безусловно, поэтому движение
ЛЮБОГО ползунка при открытом пресете превращало `null` в явный hex. Так
`#858585` и попал в документ. Теперь цвет пишется только если **трогали само
поле цвета** — липкий флаг `meColorTouched`, слушатель на `meColor`
зарегистрирован ПЕРЕД общим.

### Причина 3 — с телефона карточку нечем открыть

`.mat-card.active .mat-edit { display: block }` — карандаш был только на
активной карточке. Для остальных единственный вход — удержание 500 мс, а
v2.3b отменяет удержание по любому `pointercancel`, который iOS шлёт даже для
неподвижного пальца.

- карандаш на КАЖДОЙ карточке, тихий (`--panel2`/`--text-dim`), красный
  только на активной — сигнал a2.101 цел;
- `.mat-edit::after { inset: -6px }` — область нажатия шире значка;
- удержание отменяется движением > 8 px; `pointercancel` — как в v2.3b.

### Кнопка CLEAN

Карточка рядом с `+`: сносит всё, что не носит ни один объект **и ни один шаг
истории**, и никогда пресет. Говорит, сколько снесено. `serializeDoc` теперь
пишет только используемое + три пресета (раньше писал всю библиотеку, и
следующее открытие возвращало всё, что CLEAN убрал).

### Семь дефектов от ревьюера — все исправлены

1. документ нёс ВСЮ библиотеку; 2. CLEAN не смотрел в историю;
3. `presetDrift` ложно срабатывал; 4. тост был невидим (затирался
`toast('Opened ...')`); 5. защита была слишком широкой; 6. условный
`pointercancel` — мёртвый код; 7. сравнение цвета «отличается сейчас» вместо
«двигали».
