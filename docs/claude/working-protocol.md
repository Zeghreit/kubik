# Рабочий протокол: точность при минимуме токенов

Принят 19.09.2026. Короткая версия живёт в инструкциях проекта; здесь — полная.

## 1. `index.html` не читается целиком. Никогда

~40 000 строк ≈ 150k токенов. Два чтения за сессию — и контекст мёртв.

- Работать по карте файла: `_g.py <regex> [file] [-A n]` (grep, переживающий
  слой оболочки), `sed -n 'A,Bp'` для диапазонов.
- Никогда не вставлять файл или большой его кусок в чат.
- После патча **не перечитывать** — `_verify.py` и `node --check` скажут, если
  сломалось, дешевле любого чтения.
- Стоит завести `_map.py`: одним прогоном выдаёт все функции и секции с
  номерами строк (~200 строк вывода вместо 40 000). Пока его нет — `_g.py` по
  `^\s*(function|const .* = \(|class )`.

## 2. Агенты — это изоляция контекста, а не помощь

Агент читает двадцать файлов, в контекст сессии падает пятнадцать строк вывода.
Это основной рычаг экономии, и он же повышает точность: свежий ревьюер не имеет
предвзятости к коду, которого не писал.

| задача | агент | модель |
|---|---|---|
| разведка по коду, «где живёт X» | Explore | haiku |
| механическая пакетная правка доков/файлов | general-purpose | haiku |
| ревью написанного кода | general-purpose | opus |
| геометрия, CSG, кривые, всё с допуском | general-purpose | fable |
| проверка факта, чтение доков API | general-purpose | haiku |

Правила: независимые задачи — одним сообщением, параллельно; агенту даётся
задача и формат ответа, а не «посмотри вот тут»; не делегируются пошаговая
отладка, реализация фичи и всё, где нужен ответ Zeghreit по ходу.

**Проверено на v2.67:** fable нашёл блокер (площадь почти коллинеарного острова
в UV — шум float32, а не ноль, поэтому проходит любую проверку «измеримо ли
это» и потом рушит раскладку) и ошибку world-vs-local масштаба. Opus на ревью
починок нашёл, что подменный тест формы инвариантен к независимому масштабу U и
V, плюс пять комментариев, которых код не выполняет. Ложных тревог ни у одного.

## 3. Протокол задачи — пять шагов, всегда одни и те же

1. **Объём.** Фикс (буква) или фича (версия) — одна фраза от Zeghreit.
2. **Разведка.** grep по карте, при нужде агент. Ничего «на всякий случай».
3. **План в 3–5 строк до кода.** Здесь ловится «а надо ли это вообще» —
   полировка вместо вопроса о смысле уже стоила проекту переделок.
4. **Патч.** Python patch script с `assert old in s`, затем `_verify.py` и
   проверка дублей деклараций.
5. **Верификация.** Числа, а не рассуждения; `?debug=1` из консоли; на
   нетривиальном коде — свежий ревьюер-агент.

## 4. Контекст под наблюдением

- Чекпойнт на ~60%: сказать вслух «контекст на две трети, предлагаю закрыть
  версию и начать новый чат».
- Один чат — одна фича. После шипа новый чат дешевле, чем тащить историю.
- Конец чата: дописать `handoff-next-session.md`. Новый чат стартует с
  `CURRENT_STATE.md` + `00-INDEX.md` + handoff, а не с пересказа.

## 5. Чего не делать

Пересказывать вывод инструментов между шагами. Писать длинные технические
сводки после правки (две-три строки простым языком). Перечитывать файл «чтобы
убедиться». Предлагать рефакторинг, о котором не просили. Рассказывать, что
делали агенты — только вывод.

## 6. Дешёвый вход со стороны Zeghreit

Ошибка → сразу консоль с `?debug=1`, не описание словами. «Не работает» → одна
строка: что нажал, что ожидал, что увидел. Задача на три фичи → три сообщения,
каждая шипится отдельно.
