# Kubik — дизайн-док

Статус: черновик 23-10. Паспорт — [`PROJECT.md`](../PROJECT.md), текущее
состояние — `CURRENT_STATE.md`.

## Цель

Дать возможность лепить лоу-поли меш в браузере телефона одной рукой: без
установки, без аккаунта, без облака.

## Что это и для кого

3D-редактор на three.js, один self-contained HTML. Основной пользователь — автор
(правит модель в дороге) и любой, кто открыл ссылку `zeghreit.github.io/kubik/`.
Второе применение — вьюер и редактор внутри AssetForge (хаб, `af_preview`).

## Архитектура и поток

- Один HTML-файл, three.js через CDN (ES-модуль), без сборщика.
- Управление одной рукой: инструменты «расцветают» у пальца; ничего не
  предполагает, что именно ты делаешь (general-purpose modeller).
- Версии лежат каталогами: `v229/`, `v230/`, `v231/`, `_a21xx/`; запуск — через
  HTTP-сервер, не `file://`.

## Ограничения и цена

- Нет сборщика и зависимостей — значит, нет и модульности: всё в одном файле.
- Мобильный браузер: бюджет по памяти и по числу касаний; тяжёлые меши лагают.

## Решения (дата, что, почему)

- 2026-10-22 — старые версии (`v229/…`, `_a21xx/`) не править без причины;
  точка правды — `CURRENT_STATE.md`.
- (ранее) квады сохраняются при правке — это то, за что Kubik взят в AF.

## Открытые вопросы

- Где граница «один HTML»: когда выносить ядро в модули.
- Нужен ли импорт GLB/FBX из AF прямо в редактор.

## Чего не делаем

- Аккаунты, облачное хранение, совместная работа.
- Скульптинг с высоким полигонажем — это не ZBrush.
